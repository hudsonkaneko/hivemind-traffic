28 October 2026 · Codex for Sam · synthetic engineering evidence.

Sam asked to continue useful bounded work without Hudson's checkpoint. The
[predeclared tranche](../experiments/configs/i110_acc_stress_v1.json) extends
the earlier mild braking/stop checks to a safe requested cut-in, 4.5 m/s² leader

## Result and what it changes

All 13 verification runs passed event-realization and network/accounting gates:
six matched native/filtered pairs at seeds 731101/731102, plus one filtered
emergency repeat. Each completed all 45 requests, including eight ramp requests,
after the separately reported drain. There were no collisions, teleports or
removed trips. At the 60 s horizon, only 23–25 trips had completed and all eight
ramp trips remained active. They are counted as unfinished at H, never omitted.
Runs ended at 100.2–102.6 s, within the 90 s additional drain budget.

The canonical repeated trace and event journal are identical. Network, demand
and event-specification bytes match within every native/filtered pair; their
original inputs remained unchanged. Development seed 731001 supplied four
additional runs: ordinary, event-off, cut-in and emergency. Event-off equals
ordinary exactly. No fixture or controller was retuned from these outcomes.

The smooth controller does **not** satisfy the previous 2.05 m/s³ engineering
comfort bound in any of the seven filtered verification runs. A realized cut-in
produces a sharp response; stronger braking also exceeds comfort limits.
SUMO's final safety authority remained enabled. These failures are preserved,
not hidden behind the separate network gate.

diagnostic, not an isolated event-response effect. A speed mismatch exceeds
1e-5 m/s from the previous requested acceleration's predicted next speed. It
cannot identify a specific internal SUMO override. Native internal counters
are unavailable and remain null, not zero interventions.

Filtered emergency response reaches 4.5 m/s² braking, a minimum controlled
bumper gap of 10.777 m and minimum positive closing TTC of 2.316 s. Those are
simulator diagnostics, not road-safety thresholds. The synthetic leader actually
realizes 9 m/s² and reaches zero speed; only that actor's declared braking
capability differs from the hard-braking case. This is not calibrated physics.

Filtered-minus-native boundary-inclusive trip time at H increases by 2.0–44.2 s
across the six pairs. Ramp burden at H is unchanged because every ramp request
is still active then (346 s per cohort); that censoring does not prove no ramp
effect. The summary preserves all origin/role groups and drain outcomes. Lower
peak jerk alone cannot support a traffic-benefit or real-world comfort claim.

## Implementation and verification

Independent event JSON files are separate from permanent road geometry.
`traffic/i110_events.py` owns validation, declared cohort actor insertion,
time-based commands and request/realization journals. A cut-in must really
change physical lane and become agent_1's leader. A braking event must stop and
achieve at least 90% of requested deceleration while the controlled follower
follows. Missing/blocked/unreleased events fail that gate. All event commands
retain speed mode 31 and lane-change mode 512. Unsupported event kinds fail
closed. See the [adapter contract](i110-event-adapter-contract.md).

The baseline keeps its old non-event comfort acceptance. Stress runs separate
fixture acceptance from comfort so safety authority is never disabled to meet
a jerk target. Native lane-change XML and full traces are retained. Eight realized
ramp lane changes per run are recorded, but rejected opportunities are not
enumerated and no targeted ramp-conflict acceptance follows from these cohorts.

47 targeted tests passed across event validation/authority, exact event-off
demand, cohort counts, actual-versus-requested realization, lane identities,
graph observations, SUMO lifecycle, accounting and evidence catalog contracts.
Two pre-existing pytest timeout-marker warnings remain; the batch independently
enforces 120 s per child. Python 3.11.16 and SUMO/TraCI 1.27.1 were used.
All 17 batch children exited naturally. Report generation verified all recorded
run input/output and copied-source hashes and regenerated values from raw traces.

Evidence lives in `outputs/i110-acc-stress-20261028/`: `development-v1/`,
`verification-v1/`, `analysis-v1/`, and `tests-v1.xml` / `tests-v2.xml`. Every run has resolved
settings, exact command, seed, versions, base commit/dirty status/diff, source
snapshots, metrics, trace, event journal, native tripinfo and lane-change output.
Raw outputs remain local and ignored by Git; the source/docs checkpoint does
not include those bytes. No new result graphic was needed; the generated table
has explicit lineage in the catalog.

Final review tightened event-off acceptance to retain the ordinary comfort gate;
`post-review-gate-check.json` verifies unchanged outcomes for all 17 stored runs.
It changes no controller or event motion. The targeted suite passed again after
that gate-only correction. The first catalog build failed because a chronology
field used a string instead of a list; its failure record is retained and the
corrected catalog validates. See the [latest catalog](../outputs/evidence-catalog/20261028-stress-final/index.html).
