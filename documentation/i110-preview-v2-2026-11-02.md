# Preview braking/recovery v2 and v2.1 — 2 November 2026

Prepared by Codex for Sam after the request to fix braking/recovery, compare against the same baseline, and locate the original car.

V2.1 passes all six primary development acceptance checks. The first v2 revision failed four primary comfort cases despite removing the large v1 time costs; it is retained. V2.1 was then separately predeclared and tested, not silently substituted into v2.

That acceptance is for the declared 240 m range. At 120 m, ramp-50 still reaches
20 m/s³ and fails comfort. All six primary cases have zero motion-realization

freeze audit passes for all 32 matrix runs.

## What changed

V1 latched a fixed braking request across all conditional adjacent paths and waited for a large reserve before release. V2 replaced that latch with continuously updated following and recovery using the current route-local leader, but that leader sometimes became visible too late. V2.1 restores conditional forward-path preview, excludes side-by-side/overlapping adjacent projections, and limits adjacent requests to closing-speed matching rather than opening a following gap. Native SUMO safety and the measured-acceleration jerk filter remain active.

The continuous request uses the speed/gap structure of [SUMO 1.27.1 ACC](https://github.com/eclipse-sumo/sumo/blob/v1_27_1/src/microsim/cfmodels/MSCFModel_ACC.cpp), with a 2 s headway and 10 m reserve. It operates before the native 100 m mode boundary. It is an engineering request law, not an exact substitute for all internal safety logic. Hypothetical followSpeed calls are avoided because that implementation can update ACC mode state. Realized mismatches remain measured.
